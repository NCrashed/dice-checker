# Dice Checker

Android-приложение для статистической проверки честности игральных кубиков
(d4, d6, d8, d10, d% и d20) и для экспериментов о том, влияет ли состояние
сознания на результат броска.

## Сборка (Nix)

```sh
nix run .#build-apk     # → build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
nix run .#install       # собрать и поставить на телефон по adb (включите отладку по USB)
nix develop             # shell с flutter, JDK 17 и Android SDK
flutter test            # тесты статистики
```

Flutter, JDK, Android SDK и NDK (его требует Flutter Gradle-плагин) берутся
из nixpkgs (`androidenv`). При первом запуске скачивается около 1.5 ГБ. Сам
Gradle при первой сборке складывает свои зависимости в `~/.gradle`, поэтому
полностью офлайн-сборки (чистой Nix-деривации) здесь нет.

Скриншоты экранов без телефона (в `test_screens/out/`):

```sh
nix develop -c env SCREEN_FONT_DIR=$(nix build --print-out-paths nixpkgs#liberation_ttf)/share/fonts/truetype \
  flutter test test_screens --update-goldens
```

## Как пользоваться

1. **Кубики** — заведите каждый физический кубик отдельно.
2. **Броски** — кидайте и нажимайте выпавшую грань. Внизу по ходу обновляются
   вердикт и байесов фактор. Если ошиблись, нажмите «отменить».
3. **Честность** — гистограмма с 95% интервалами, график накопления
   свидетельств, χ², отклонения по граням и оценка того, какой перекос уже
   различим при текущем числе бросков.
4. **Сознание** — состояния (метки) и цели:
   - выберите состояние в верхнем ряду («Нейтрально», «Намерение», свои варианты);
   - включите «новая после броска»: перед каждым броском приложение
     выбирает случайную цель (`Random.secure`), и вы концентрируетесь на ней;
   - чередуйте состояния блоками, а «Нейтрально» с теми же случайными целями
     используйте как контроль.

## Статистика

- **Честность.** Байесов фактор (BF) сравнивает гипотезу «все грани
  равновероятны» с гипотезой «вероятности граней отклоняются от 1/k»
  (симметричный априор Дирихле с типичным отклонением ±15%). Плоский
  Дирихле(1) ожидал бы нереально сильных перекосов и объявлял бы «честным»
  почти любой кубик. BF обновляется после каждого броска и, в отличие от p-value,
  не искажается, если смотреть на результат постоянно и остановиться в любой
  момент. Пороги: |log₁₀ BF| ≥ 0.5 — умеренные свидетельства, ≥ 1 — сильные.
- **χ² Пирсона** с p-value показан для сравнения. Он надёжен примерно от
  5·k бросков, где k — число граней.
- **Различие между состояниями.** BF «у каждого состояния своё распределение»
  против «распределение общее», плюс χ² таблицы сопряжённости.
- **Попадания в цель.** Доля попаданий против шанса 1/k: интервал Уилсона,
  BF (априор Beta с центром в 1/k и разбросом ±50%) и односторонний z-тест. Цель выбирается случайно,
  поэтому перекос самого кубика не даёт ложного эффекта.

Сколько нужно бросков: чтобы заметить у d20 перекос порядка ±30% на одной
грани, нужны сотни бросков. Перекосы в несколько процентов видны только
на тысячах.

## Данные

Данные хранятся в JSON-файле в приватной папке приложения (без плагинов:
путь отдаёт `MainActivity.kt`). В меню главного экрана есть
экспорт CSV и резервная копия JSON через буфер обмена, а также восстановление
из неё.
